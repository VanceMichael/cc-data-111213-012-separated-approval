# 双人复核门户的角色隔离自动化

separated-approval 用于合作资料的本地查看和来源保存。当前版本支持人工触发的整份资料查看与字节级归档，资料对象按内容摘要保存，每次领取保留单独回执。自动组织领域资料的能力与人工查看入口分别演进。

本版本增加**双人复核辅助流程**：制单员整理资料，符合规则的交给另一位获授权人员确认；敏感事项停在人工。自动化只协助核对、归档与版本比对，绝不自动批准付款，所有账号均为仓库内合成身份，不对真实金融系统操作。

## 运行环境

使用 Node.js 22。依赖已锁定；首次准备执行 `npm ci --ignore-scripts`，正式运行无需下载资料或软件。全部样例使用合成数据与本机来源，不连接生产系统。

```bash
npm run check
npm test
npm run demo
npm run review-demo
```

`npm run demo` 在临时目录实际读取资料、归档并重新核验摘要，退出时清理临时内容。浏览器项目还会启动本地门户和 Chromium 并完成可见页面查看；浏览器在环境准备阶段安装，正式运行不下载。正常演示应在九十秒内结束（当前实测约数秒）。

## 双人复核辅助流程

- `src/policy.js`：纯规则模块。资料“具体版本”由**版本号 + 内容快照**（金额与附件摘要的哈希）共同确定；金额超过阈值、缺可核验附件、命中敏感关键词或人工通道事项一律判定为人工处理。
- `src/assistant.js`：人机协作引擎。制单员与复核员各自持有**独立浏览器上下文**（独立 cookie 与存储），分别走门户真实登录；代码不复制 cookie、不手工构造会话，身份只以服务端 `/api/identity` 的 JSON 为准，不依据页面按钮是否可点。
- 复核人提交的每条意见都绑定自己审阅时的（版本号、快照）。制单后金额或附件一旦改变，版本递增、快照变化，旧意见原样保留但标记为**已失效**，沿用旧页面提交会被服务端以 409 拒绝。
- 会话过期、角色回退（上下文挂着另一身份）、版本失效与敏感事项分别抛出类型化的 `WorkflowHalt`，引擎停止并等待；重新登录后重新拉取并核对当前版本再继续，不静默继承旧状态。
- `npm run review-demo` 顺序演示四个场景：① 制单员修改已复核资料，旧页面复核被拒、旧意见失效；② 复核员重新审阅新版本后同意；③ 超阈值敏感事项引擎暂停且服务端拒绝自动同意；④ 清空会话模拟过期，重新登录核对后登记人工暂缓。输出为结构化 JSON 报告。

## 本地来源门户

`fixtures/portal/` 是合成业务来源的页面与交互脚本，由 `src/portal.js` 提供本地 HTTP 服务；浏览器功能测试直接操作这些页面。

运行 `npm start -- --port 4173` 后访问终端显示的本地地址，按 Ctrl+C 停止；端口也可由 `PORT` 配置。

- 门户页 `/`：两种演练身份（制单员甲 `maker-A`、复核员乙 `reviewer-B`），展示资料编号、版本、内容快照、规则结论、附件摘要与全部复核意见。
- 只读审计页 `/audit.html`：仅通过 GET 读取 `/api/audit`，无任何写操作入口；说明两个人各自处理过哪个版本、哪些意见已随资料变更失效，并给出完整审计事件链。
- 服务端是最终防线：制单人不能自审、匿名写操作返回 401、伪造或过期快照返回 409、敏感事项的自动通道同意返回 403。

## 资料操作

```bash
npm run cli -- inspect fixtures/portal.json
npm run cli -- capture fixtures/portal.json .local/archive
npm run cli -- list .local/archive
npm run cli -- review-demo
```

`capture` 只表示来源字节已保存，不声称领域流程已自动完成。已有查看功能只展示现有资料，不替代业务接纳判断。`scripts/create-fixtures.js` 用于维护者重建合成资料（含附件字节与摘要）；运行与测试直接读取已提交的资料。

## 目录约定

- `src/domain.js`：现有领域读取和查看接口。
- `src/archive.js`：内容对象、来源回执与完整性检查。
- `src/policy.js`：版本快照与敏感规则（服务端与协作引擎共用）。
- `src/assistant.js`：独立上下文的人机协作引擎与类型化暂停。
- `src/demo.js`：四场景演示编排与结构化报告。
- `fixtures/`：本地资料、合成附件与领域配置。
- `test/`：规则、API 强制约束、浏览器端到端与审计页验证，使用独立临时目录。

## Linux 环境

`Dockerfile` 使用 Node.js 22 镜像；浏览器项目使用包含 Chromium 的运行镜像。可执行 `docker build -t separated-approval:local .` 后运行 `docker run --rm --network none separated-approval:local npm test`。测试中的 HTTP、MQTT 和门户都仅绑定回环地址；不需要第二个容器。构建阶段准备依赖，运行时不安装依赖。
